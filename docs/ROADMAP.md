# Master Roadmap — BizOrder Assistant

> 목표: **B2B 통신 상품의 가격·할인 정책을 모델링하고, 견적 계산 → 확정 Snapshot → 가입 접수 준비까지 시연 가능한 포트폴리오 웹 시스템을 완성한다.**

이 문서는 BizOrder Assistant의 **진행률 기준(Source of Truth)** 이다.  
프로젝트 범위와 제품 의도는 `PROJECT_PLAN.md`, 도메인 정의는 `DOMAIN.md`, 개발 절차는 `DEVELOPMENT_WORKFLOW.md`를 따른다.

## 진행률 계산 규칙

- 전체 진행률은 아래 세부 항목의 **가중치 합계(100%)** 로 계산한다.
- `[x]`는 기본 브랜치에서 구현·테스트·문서 등 완료 근거가 확인되는 경우에만 표시한다.
- 열린 Issue, 작업 중 브랜치, 미병합 PR, 아이디어만 있는 상태는 완료로 계산하지 않는다.
- 부분 완료를 체감으로 퍼센트화하지 않는다. 각 체크 항목의 완료 기준을 충족했을 때 해당 가중치를 반영한다.
- 실제 통신사 내부 데이터나 실제 고객 개인정보는 사용하지 않는다.
- 범위가 바뀌면 총합 100%를 유지하도록 가중치를 함께 조정한다.

- [x] **2%** Product / PricingPolicy / DiscountRule / Quote / Snapshot / Checklist 핵심 도메인 정의
- [x] **2%** Issue → Branch → PR → Squash Merge 개발 워크플로 및 템플릿 구성
- [x] **2%** 초기 개발 Backlog를 Issue #1~#14로 분해

**완료 기준:** 저장소 문서만 읽어도 무엇을 만들고, 무엇을 만들지 않으며, 어떤 순서와 규칙으로 개발하는지 설명할 수 있다.

## 핵심 End-to-End 시나리오

```text
ADMIN
  └─ 가상 Product / PricingPolicy / DiscountRule 관리
             ↓
STAFF
  └─ 상품·수량·약정 조건 입력
             ↓
      유효 가격 정책 조회
             ↓
        할인 규칙 평가
             ↓
        최종 견적 계산
             ↓
      접수 준비 Checklist
             ↓
          견적 확정
             ↓
   가격·할인 결과 Snapshot 보존
```

## 현재 기준 진행률

기본 브랜치에서 확인된 체크 항목 기준: **16%**

- M0: **8 / 8**
- M1: **8 / 8**
- M2~M8: **0**
- Issue #1~#2가 완료되어 개발 기반 구성이 끝났으며, 다음 작업은 Issue #3 Product 도메인 및 CRUD 구현이다.

> 이 수치는 “체감상 8%”가 아니라 이 문서에서 정의한 완료 항목의 가중치 합이다.

- 고객 CRM

- 통계 대시보드
- 실제 결제·정산
- PDF 견적서
- 복수 사업장

## 운영 원칙

- 진행률과 완료 여부는 이 파일을 기준으로 관리한다.
- 일정 가이드는 `PROJECT_PLAN.md`의 12주 계획을 참고하되, 실제 우선순위는 미완료 마일스톤과 Issue 의존성을 따른다.
- README에는 상세 체크리스트를 중복하지 않고 현재 단계와 이 문서 링크만 유지한다.
