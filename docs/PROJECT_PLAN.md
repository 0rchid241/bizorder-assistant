# BizOrder Assistant 프로젝트 기획서 v0.2

## 1. 프로젝트 목적
B2B 통신 상품을 상담하는 직원이 고객 요구조건에 맞는 상품을 선택하고, 현재 유효한 가격·할인 정책을 적용한 견적을 계산한 뒤 공식 가입 접수 전에 필요한 사항을 확인할 수 있도록 지원한다.

핵심 목표는 실제 통신 B2B 업무의 규칙을 분석해 Java/Spring 기반 도메인 모델과 비즈니스 로직으로 구현하는 경험을 포트폴리오로 보여주는 것이다.

## 2. 프로젝트 성격
이 시스템은 특정 통신사의 공식 시스템, SWING과 같은 BSS, 고객 CRM을 대체하지 않는다. 실제 고객 개인정보나 실제 통신사의 비공개 요금정책도 저장·복제하지 않는다. 시연 데이터는 가상 데이터를 사용한다.

## 3. 핵심 문제
- 약정기간별 가격
- 상품 결합 조건
- 기간 한정 할인
- 할인 중복 가능 여부
- 정책 우선순위
- 정책 유효기간
- 정책 변경 후에도 과거 견적 결과 보존

따라서 단순 CRUD보다 **정책 기반 견적 계산과 견적 시점의 결과 보존**을 핵심 문제로 삼는다.

## 4. 사용자
### STAFF
견적 조건 입력, 상품 선택, 예상 요금 계산, 할인 확인, 견적 확정, 접수 준비 체크리스트 확인.

### ADMIN
상품, 가격 정책, 할인 정책, 접수 필수항목 관리.

## 5. MVP 흐름
```text
견적 조건 입력
 ↓
상품 선택
 ↓
유효 가격 정책 조회
 ↓
할인 규칙 계산
 ↓
최종 예상 요금
 ↓
접수 준비 체크리스트
 ↓
견적 확정
```

## 6. MVP 기능
### Product
상품 등록/조회/수정, 활성 상태, 카테고리.

### PricingPolicy
월 이용료, 설치비(필요 시), 약정기간, 적용 시작/종료일.

### DiscountRule
할인 대상·조건·방식(정액/정률), 유효기간, 중복 가능 여부, 우선순위. 초기에는 기간 한정 프로모션도 DiscountRule로 표현한다.

### Quote
상품 및 수량 선택, 가격 조회, 할인 계산, 최종 금액 산출, 저장.

### Quote Snapshot
확정 시 상품명/코드, 적용 가격, 할인, 최종 금액을 보존하여 이후 정책 변경의 영향을 받지 않게 한다.

### Checklist
상품별 접수 전 확인사항과 견적별 확인상태를 관리한다.

## 7. MVP 제외
고객 CRM, 실제 개인정보, AI 추천, 통계 대시보드, 알림, 실제 SWING 연동, 결제/가입접수, 실제 내부 상품·요금 복제, PDF 견적서, 복수 사업장.

## 8. 초기 도메인
```text
Product
 ├─ PricingPolicy
 └─ DiscountRule

Quote
 └─ QuoteItem
      └─ Product
```

후속 후보: RequiredItem, QuoteChecklist, User, Role, AuditLog.

## 9. 설계 원칙
1. 개인정보 최소화
2. 가격·할인 정책 하드코딩 최소화
3. 확정 견적 불변성
4. 핵심 도메인 로직 단위 테스트

## 10. 핵심 테스트
- 현재 유효한 가격정책만 선택되는가?
- 계약기간이 다른 정책은 제외되는가?
- 비활성 상품은 견적에 포함할 수 없는가?
- 조건을 만족하는 할인만 적용되는가?
- 만료된 할인은 제외되는가?
- 중복 불가 할인 충돌을 처리하는가?
- 할인 후 비정상적인 음수 요금을 방지하는가?
- 정책 변경 후에도 확정 견적은 동일한가?

## 11. 기술 스택
Backend: Java, Spring Boot, Spring Web, Spring Data JPA, Spring Security, Validation, JUnit 5  
Database: PostgreSQL  
Frontend: React, TypeScript  
Infrastructure: Docker, Docker Compose, GitHub Actions

## 13. 성공 기준
프로젝트 목적, CRM/BSS 비대체 이유, 정책 모델링, 할인 충돌, 과거 견적 보존, 개인정보 최소화, 테스트 전략, 실제 도입 시 추가 확인사항을 코드와 문서로 설명할 수 있어야 한다.

## 14. 실제 업무 정보 반영 원칙
추가 정보를 알게 되어도 기능을 무작정 늘리지 않는다. 견적, 체크리스트, 재입력 문제 등 현재 핵심 범위 안에서 우선순위만 조정하며 3개월 완성을 우선한다.
